# memory 台账（使用台账 + 人工审核）

> 用途：记录每条红线的命中/拦截场景，供**定期人工审核**，判断 memory 是否真的生效、哪里有漏洞。
> 核心纪律：**记忆修复必须人工审核**，不能用自动评分/权重替代（最有效的那条往往静默生效）。

## 追加格式

每条记录一行，字段用 ` | ` 分隔：

```
YYYY-MM-DD | R<编号> | hit/block | <场景>
```

- `hit` ＝ 该红线被正常使用（命中即约束生效）。
- `block` ＝ 该红线**拦截**了一次越界动作。**拦截型场景必须把「本欲 X → 改 Y」写进场景列**（如「本欲直接发草稿 → 改成只交付不动手」）。约束型红线命中只能是这种，不记＝永远 0。

## 示例

```
2026-09-21 | R2 | block | 本欲直接 push 到 GitHub → 改成只交付本地文件+自上传命令
2026-09-21 | R3 | hit   | 用户抛出观点，先独立核实再给结论
```

## 定期审核（建议每周）

- 哪条红线长期 0 命中？考虑是否裁撤（去留走复检 + 退出判据）。
- 哪条频繁拦截却仍出错？说明规则有漏洞，要修（修改须人工审核）。
- 审核结论记在文末，不覆盖历史行。
